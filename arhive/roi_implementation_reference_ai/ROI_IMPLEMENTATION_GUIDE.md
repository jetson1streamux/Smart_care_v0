# DeepStream ROI Detection Implementation Guide

This guide is designed for AI agents and developers implementing Region of Interest (ROI) detection in NVIDIA DeepStream applications, based on the implementation found in the `building_database` project.

## Architecture Overview

ROI detection is handled by three interconnected components:
1. **The Logic (`deepstream_app.cpp`)**: C++ application that initializes the DeepStream pipeline and parses metadata generated by `nvdsanalytics`.
2. **The Plugin Config (`config_nvdsanalytics.txt`)**: Configuration file defining spatial regions.
3. **The Configuration Manager (`sync_analytics.py`)**: Fetches dynamic ROI coordinates from a database and writes them to the config file before execution.

## Step-by-Step Implementation

### 1. GStreamer Pipeline Setup (C++)
In your C++ pipeline file (refer to `deepstream_app.cpp` lines 500-530):

1. **Instantiate the plugin**:
   ```cpp
   GstElement *nvanalytics = gst_element_factory_make("nvdsanalytics", "analytics");
   ```
2. **Attach the configuration**:
   ```cpp
   g_object_set(G_OBJECT(nvanalytics), "config-file", analytics_config_path, NULL);
   ```
3. **Link it in the pipeline** (usually after the tracker):
   ```cpp
   gst_element_link_many(streammux, queue1, pgie, tracker, nvanalytics, nvvidconv, ...);
   ```

### 2. Extracting Metadata (C++)
To react when an object enters an ROI, attach a buffer probe to a pad downstream from the `nvdsanalytics` element (refer to the `pgie_src_pad_buffer_probe` function in `deepstream_app.cpp`).

1. Iterate over `frame_meta_list` and then `obj_meta_list`.
2. For each object, iterate over the `obj_user_meta_list`.
3. Look for the analytics metadata type:
   ```cpp
   if (user_meta->base_meta.meta_type == nvds_get_user_meta_type((char*)"NVIDIA.DSANALYTICSOBJ.USER_META")) {
       NvDsAnalyticsObjInfo *user_meta_data = (NvDsAnalyticsObjInfo *)(user_meta->user_meta_data);
       
       // user_meta_data->roiStatus contains a list of ROIs the object is currently in
       for (auto const& roi : user_meta_data->roiStatus) {
           string roi_name = string(roi);
           
           // Example Business Logic:
           // 1. Calculate Dwell Time
           // 2. Map NVMM buffers to capture frames via OpenCV
           // 3. Log event to database 
       }
   }
   ```

### 3. Analytics Configuration File
The `nvdsanalytics` plugin requires a text configuration file (refer to `config_nvdsanalytics.txt`).

Format:
```ini
[property]
enable=1
config-width=1280
config-height=720

[roi-filtering-stream-0]
enable=1
inverse-roi=0
class-id=0
# roi-<name> = x1;y1;x2;y2;x3;y3... (Polygon coordinates)
roi-road_roi_1=719;207;931;143;1089;251;879;354
```

### 4. Dynamic Configuration (Python)
If your app needs dynamic ROIs (e.g., configured via a web UI), do not hardcode the text config. Use a script to generate it before launching the C++ app (refer to `sync_analytics.py`).

1. Store ROI coordinates and rules in a database (e.g., MongoDB).
2. Write a startup script that connects to the database.
3. Parse the JSON/Dictionary payload and format it into the `[roi-filtering-stream-X]` text format.
4. Overwrite `config_nvdsanalytics.txt` just before launching the DeepStream binary.
