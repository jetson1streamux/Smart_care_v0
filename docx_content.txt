1. Purpose
This document defines the functional requirements for a Risk-Based Action Tracking and Proactive Monitoring (RBATPM) capability within SmartCare (the Hospital Information System). The objective is to move financial and stock-transaction oversight from a reactive, post-transaction audit model to a proactive, near real-time model — by correlating high-risk transactions at key hospital counters with live and recorded video evidence from the Video Analytics System (VAS), before or at the moment the transaction is completed.
2. Scope
2.1 In Scope
Identification of key financial and stock-handling counters across the hospital (Billing, Cash Counter, Pharmacy, Stores/Inventory, Insurance Desk) as monitored points.
Risk-rule evaluation of transactions initiated by staff at these counters within SmartCare.
API-based integration where SmartCare triggers the VAS to start/mark recording of the relevant camera feed for a flagged transaction.
A CCTV Alert Dashboard within SmartCare for reviewing, verifying, and escalating flagged transactions with linked video evidence.
Subscription-based control over which staff, counters, or rules are actively monitored.
2.2 Out of Scope
Configuration and internal video-analytics algorithms of the VAS itself (e.g., facial recognition, motion-detection tuning) — treated as a vendor-managed black box exposed via API.
Physical camera installation, network cabling, and storage infrastructure for video retention.
Legal / statutory retention policy for video evidence (to be governed by a separate data-retention policy).

4. End-to-End Workflow
The workflow below describes the full lifecycle of a monitored transaction, from staff action in SmartCare to closure of the review.
Phase 1 — Trigger
Staff performs a financial or stock action at a monitored counter in SmartCare (e.g., cash refund, discount override, bill cancellation, stock issue).
SmartCare's rule engine evaluates the action against configured risk rules and computes a Risk Score (High / Medium / Low).
SmartCare checks the Subscription (Y/N) flag for the relevant staff / counter / rule combination.
If Subscription = N: the transaction is logged normally in SmartCare; no VAS call is made; workflow ends.
If Subscription = Y: workflow proceeds to Phase 2.
Phase 2 — Capture
SmartCare calls the VAS API (start-recording trigger) passing Staff ID, Counter/Camera ID, Transaction ID, timestamp, and pre-/post-event buffer duration.
VAS starts or marks the recording for the mapped camera stream and returns a Clip ID, Live Stream reference, Recording Status and Camera Health Status.
SmartCare evaluates the VAS response:
If the response indicates failure or the camera is offline: SmartCare raises a parallel “Monitoring Gap” alert, since a risk-flagged transaction with no video coverage is itself a risk signal.
If successful: SmartCare stores the Clip ID / Stream reference against the Transaction ID for display on the dashboard.
Phase 3 — Alert & Review
The flagged transaction appears on the SmartCare CCTV Alert Dashboard with Module, Staff ID, Action, Risk Score and Counter details.
A reviewer (supervisor / auditor) opens the alert and uses View Live Stream, View Log, and/or View Recording with Narrative to examine the transaction.
The reviewer records a narrative or remarks, cross-referencing the transaction log against the video evidence.
Phase 4 — Disposition & Closure
The reviewer marks the transaction outcome as Verified-Clean, Verified-Discrepancy, or Escalated.
Escalated items are routed to the Risk / Audit / Security team together with the evidence package (video clip, transaction log, narrative).
SmartCare updates the transaction status and audit trail; dashboard KPIs (turnaround time, escalation rate, monitoring-gap count) are refreshed.

6. Integration — API Contract (SmartCare → VAS)
SmartCare acts as the API caller (client); VAS acts as the responder (server). All calls are triggered only when Subscription = Y for the relevant staff/counter/rule.
6.1 Request — SmartCare to VAS
Parameter
Description
Staff ID
Staff member who triggered the action
Module
Source module (Billing, Pharmacy, Stores, Cash Counter, Insurance Desk, etc.)
Action Type
Transaction type (Refund, Discount Override, Stock Issue, Bill Cancellation, etc.)
Transaction ID
Unique reference to the SmartCare transaction
Counter / Camera ID
Physical counter mapped to the camera(s) covering that location
Timestamp
Date/time of the triggering action
Risk Score / Flag
Risk level computed by SmartCare's rule engine (High / Medium / Low)
Pre-buffer Duration
Seconds before the trigger to include in the recording (e.g., –30s)
Post-buffer Duration
Seconds after the trigger to continue recording (e.g., +60s)
Subscription (Y/N)
Confirms active monitoring status; gates whether the call is made at all
Callback URL (optional)
Endpoint for VAS to notify SmartCare asynchronously once the clip is finalized

Parameter
Description

Recording / Processing / Ready / Failed

Online / Offline / Degraded

6.3 Exception Handling Logic (within SmartCare)
If Request Status = Failure or Camera Offline: raise a secondary “Monitoring Gap” alert alongside the original transaction alert.
If Subscription = N: skip the VAS call entirely; log the transaction normally without triggering monitoring.
Store the returned Clip ID / Stream reference against the Transaction ID so the dashboard can render View Live Stream and View Recording actions directly.
If the VAS API call times out, retry per an agreed retry policy (e.g., 2 retries with backoff) before logging the attempt as failed.

7.3 Risk Indicator Legend
High
Immediate reviewer attention required (e.g., large refund, after-hours cancellation)
Medium
Review within same shift (e.g., discount override above threshold)
Low
Auto-logged; sampled/periodic review only
Monitoring Gap
Video coverage unavailable for a flagged transaction — treated as high priority regardless of original risk score
7.4 Alert Detail View
Recording playback panel (embedded, linked via VAS Clip ID).
System log trail showing transaction sequence (initiation, amount entry, risk-engine flag, VAS trigger, confirmation).
Reviewer narrative field — free text, time-stamped and attributed to the reviewer.
Verify Transaction control — captures outcome (Verified-Clean / Verified-Discrepancy / Escalated) and routes accordingly.
7.5 Monitored Counters Panel
List of all monitored counters with Camera ID, live health status (Online/Offline), and Subscription (Y/N) status.
Enables the reviewer to identify at a glance which counters currently lack video coverage.
7.6 Escalation Queue Panel
Running list of transactions escalated to Risk/Audit/Security, with status of investigation closure.

Final risk-rule catalog and exact thresholds (refund limits, discount %, after-hours definition, cancel-rebill pattern detection, etc.).
Escalation SLA — maximum time an alert may remain unreviewed before automatic escalation.
Video evidence retention period and storage ownership (SmartCare vs. VAS vendor).
Retry policy and timeout thresholds for the SmartCare → VAS API call.
Role-based access matrix sign-off (Section 8) with Finance, Audit and Security stakeholders.
